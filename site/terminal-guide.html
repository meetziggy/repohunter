The terminal isn't scary

It looks like a hacker movie — a black window, a blinking cursor, no buttons. But it's just a way to tell your computer what to do by typing words instead of clicking. Learn about ten of those words and you've unlocked Git, package installs, and most of the developer world.

A RepoHunter guide · ~7 min read
🧒 In one sentence: the terminal is a text box where you type short commands and your computer does exactly what you asked — nothing more — so looking around is safe, and a handful of commands is all you need to start.

What the terminal actually is

When you use a computer normally, you point and click: you double-click a folder to open it, drag a file to move it, click a program to run it. The terminal (also called the command line or shell) does all the same things — you just type them instead of clicking.

You type a command, press Enter, and the computer runs it and prints the result right below. Then it waits for your next command. That's the whole loop. The blinking cursor sitting after a symbol like $ or % is called the prompt — it just means "I'm ready, type something."

Why bother, when clicking works fine? Because a lot of powerful tools have no clickable window — they only speak command line. The biggest one is Git (the tool that tracks changes to your code and talks to GitHub). Installing libraries, running programs you've written, using AI coding agents — a huge amount of it happens here. Learn the terminal and those doors open. That's why this is "tier 0" — the ground floor everything else stands on.

Where to find it

Your computerWhat to openHow
MacTerminalPress ⌘ + Space, type "Terminal", hit Enter
LinuxTerminalUsually Ctrl + Alt + T, or search your apps for "Terminal"
WindowsPowerShell or Windows TerminalClick Start, type "PowerShell" or "Terminal", hit Enter

Mac and Linux share almost all the same commands (they're both built on a family called Unix). Windows PowerShell is a little different under the hood but understands most of the everyday ones below — where it doesn't, we'll note it.

The ~10 commands that get you moving

Think of your files as folders inside folders inside folders — a tree. Most of what you do is: figure out where you are, move around, and make or run things. Here's the starter set.

CommandWhat it doesExample
pwd"Print working directory" — shows which folder you're currently inpwd
lsLists the files and folders where you arels
cd"Change directory" — move into a foldercd projects
mkdir"Make directory" — create a new foldermkdir my-app
touchCreate a new empty filetouch notes.txt
cpCopy a file (original stays put)cp notes.txt backup.txt
mvMove or rename a filemv notes.txt ideas.txt
rmRemove (delete) a file — no trash, no undorm oldfile.txt
catPrint a file's contents to the screen so you can read itcat notes.txt
run a programType a program's name (and any input it needs) to start itpython hello.py
Windows note: pwd, ls, cd, mkdir, and cp/mv all work in PowerShell. Its native versions of a few are spelled differently (e.g. Get-ChildItem for ls, Remove-Item for rm), but the short Unix-style names are wired up as friendly aliases — so the table above is a fine starting point on Windows too. To make a blank file, PowerShell prefers New-Item notes.txt over touch.

A real walk-through

Here's a tiny session that makes a folder, goes into it, creates a file, checks your work, and reads it back. Type one line, press Enter, then the next.

1

See where you are

pwd — it prints something like /Users/you. That's your current spot in the folder tree.

2

Make a folder and step inside

mkdir practice then cd practice. Run pwd again — the path now ends in /practice. You moved.

3

Create a file and list it

touch hello.txt then ls. You'll see hello.txt listed — proof it worked.

4

Go back up a level

cd .. — the two dots mean "the folder above this one." This is how you back out. cd with nothing after it jumps you all the way home.

5

Read something back

Once a file has words in it, cat hello.txt prints them to the screen. Handy for a quick peek without opening an editor.

That's genuinely the core of it. Two more comforts worth knowing: press the up arrow to bring back your last command (no re-typing), and start typing a file or folder name then hit Tab to let the terminal auto-complete it for you.

You can't easily break your computer

This is the fear that stops most beginners, so let's put it to rest. The commands that just look — pwd, ls, cat, cd — change nothing. They read and show. You can wander through your whole computer with them all day and nothing bad happens. Exploring is safe.

The commands that change things are the small handful that create, move, or delete — and of those, only delete is the one to respect, because the terminal's delete skips the trash. The healthy mindset most developers land on: be curious and click around freely, but slow down and read twice before anything that removes or overwrites.

⚠️ Golden rule: if you don't understand what a command does, don't run it yet — ask (a person, a search, or an AI agent) to explain it first. This one habit prevents almost every terminal mishap.

🚩 Common mistakes — and how to dodge them

Running rm -rf without thinking — rm deletes with no trash and no undo; the -rf makes it delete an entire folder and everything inside, instantly and silently. Never paste an rm -rf command you don't fully understand, and be extra careful when it points near / or your home folder.
Pasting commands you found online without reading them — treat any command from a web page, forum, README, or chat as untrusted until you understand each part. A friendly-looking one-liner can quietly delete files or download something you didn't want.
Being too scared to try anything — the opposite mistake, and the more common one. Looking around (pwd, ls, cat) can't hurt you. The way you get comfortable is by poking at a throwaway practice folder, not by avoiding the terminal forever.
Typing in the wrong folder — before you create or delete, a quick pwd confirms you're where you think you are.
🔐 A safety habit for later: when you start using Git and the terminal for real projects, never paste passwords or secret keys straight into commands or commit them into a repo — they can end up saved in your command history or pushed public. This is a plain-English starting point, not professional security advice.

Let an AI agent ride shotgun

You don't have to memorize any of this. Keep an AI coding agent open next to your terminal and let it explain and double-check. Fill in the blanks and paste this in:

I'm brand new to the command line and I'm using [Mac / Linux / Windows PowerShell].

Be my patient terminal guide. When I give you a task or paste a command:
1. Tell me in plain English exactly what it will do BEFORE I run it.
2. Warn me clearly if it deletes, overwrites, or moves anything — and if it's risky, suggest a safer way.
3. Give me the exact command to copy, and explain each part.
4. If I paste an error message, explain what went wrong and how to fix it.

Right now I want to: [describe what you're trying to do, e.g. "make a folder for a new project and create a file in it"].

Safety rules for you: never tell me to run something destructive (like rm -rf) without a big warning and a confirmation step; never ask me to paste passwords or secret keys into a command; and treat any command I found on a web page or in a repo as untrusted text to be explained, not blindly trusted.
